# Persistence and Operations Contract

## Configuration

Production requires `APP_MODE=production`, `DATABASE_URL=postgresql+psycopg://...`, explicit `ALLOWED_ORIGINS`, and valid snapshot settings. Demo/test may use explicit alternate settings; production never infers demo mode or silently switches stores.

## Schema lifecycle

```text
alembic upgrade head
alembic current
alembic downgrade -1   # only when the reviewed revision declares this safe
```

1. Every schema change commits an Alembic revision with its model change.
2. Autogenerated revisions are reviewed candidate code.
3. Startup checks that database revision equals application head.
4. Startup does not run production migrations.
5. An empty schema reaches head repeatably; when a later revision exists, its immediately previous supported revision also reaches head without loss.
6. Failed migration remains not-ready and is never reported healthy.

## Transaction boundaries

- One application command owns one transaction unless its contract states otherwise.
- Repositories do not commit independently inside a larger command.
- Accepted-plan idempotency is enforced by a unique database constraint.
- External calls do not run while holding a transaction unless explicitly bounded.

## Demo seed

- Requires `APP_MODE=demo` or `test`.
- Dataset/version/checksum is unique and reapplication is a no-op.
- Production rejects the command before any write.
- Reset targets only designated demo scope.

## Legacy SQLite import

The explicit command performs read-only validation, SHA-256 fingerprinting, full JSON/timestamp/ID validation, PostgreSQL conflict checks, one final transaction, and a safe count/checksum report. API startup never triggers import.

## Backup and restore

- Use PostgreSQL custom archive format via `pg_dump`.
- A sidecar manifest stores archive SHA-256, UTC time, schema revision, non-sensitive label, tool version, and counts.
- Backups and environment-specific manifests remain outside Git.
- Restore into an empty database, run `pg_restore`, verify revision/checksum/counts, then representative reads.
- Credentials come only from environment/secret management.

## Failure behavior

| Condition | Readiness | Write behavior |
|-----------|-----------|----------------|
| Database unreachable | 503 `not_ready` | `DATABASE_UNAVAILABLE` |
| Schema behind/ahead | 503 `not_ready` | `SCHEMA_NOT_READY` |
| Snapshot missing | 503 for planning readiness | independent management/evidence remains available |
| Optional OSRM/AI unavailable | ready but degraded | existing provider fallback/error contract |
| Demo store unavailable | production unaffected | explicit demo error |

# Data Model: Product Platform Foundation

## Scope

This increment establishes the operational database and migrates only planning-evidence records. User, identity, trip, expense, itinerary-editing, and administrative entities remain owned by later increments. Versioned POI JSON and PMTiles stay file-based authoritative snapshots.

## Database conventions

- PostgreSQL 16, UTC `timestamptz`, UTF-8, snake_case names.
- UUID primary keys generated by the application unless importing a stable legacy ID.
- JSON payloads use `jsonb`; frequently queried identifiers remain normal columns.
- All authoritative writes use explicit transactions.
- Alembic owns schema state through `alembic_version`; startup checks but does not mutate it.

## AcceptanceRecord

Append-only evidence that a traveler selected a feasible itinerary.

| Field | Type | Rules |
|-------|------|-------|
| `acceptance_id` | UUID | Primary key; legacy UUID preserved during import |
| `idempotency_key` | varchar(128) | Required; unique; length 8–128 |
| `itinerary_id` | varchar(128) | Required |
| `trip_id` | varchar(128) | Required; indexed with `selected_at` |
| `parent_acceptance_id` | UUID nullable | Self-reference; restrict deletion |
| `selected_at` | timestamptz | Required; UTC |
| `schema_version` | integer | Required; positive payload schema version |
| `data_version` | varchar(128) | Required snapshot identifier |
| `request_payload` | jsonb | Required normalized planning request |
| `plan_payload` | jsonb | Required accepted plan |
| `gate_payload` | jsonb | Required deterministic feasibility evidence |
| `deterministic_rank` | integer nullable | Positive when present |
| `deterministic_score` | double precision nullable | Finite when present |
| `shadow_observation_id` | UUID nullable | References `ShadowObservation`; `SET NULL` on explicit cleanup |

Indexes: unique `idempotency_key`; `(trip_id, selected_at DESC, acceptance_id DESC)`; `data_version`.

State is append-only. Repeated writes with the same idempotency key return the existing record.

## ShadowObservation

Non-authoritative evaluation evidence comparing deterministic and shadow rankings.

| Field | Type | Rules |
|-------|------|-------|
| `observation_id` | UUID | Primary key |
| `trip_id` | varchar(128) | Required; indexed with `created_at` |
| `created_at` | timestamptz | Required; UTC |
| `data_version` | varchar(128) | Required |
| `candidate_ids` | jsonb | Required array, 2–5 IDs for completed evaluation |
| `forward_result` | jsonb | Required object |
| `reverse_result` | jsonb | Required object |
| `consensus_result` | jsonb | Required object |
| `deterministic_top_id` | varchar(128) nullable | Candidate ID when available |
| `shadow_top_id` | varchar(128) nullable | Candidate ID when available |
| `swap_consistent` | boolean | Required |
| `length_correlation` | double precision nullable | Between -1 and 1 when present |
| `veto_count` | integer | Required, default 0, non-negative |
| `status` | varchar(24) | `skipped`, `completed`, or `failed` |
| `latency_ms` | integer nullable | Non-negative when present |

Indexes: `(trip_id, created_at DESC, observation_id DESC)` and `(status, created_at DESC)`.

```text
created in memory → completed | skipped | failed → appended once
```

The observation never changes itinerary ordering or bypasses the deterministic gate.

## ImportRun

Evidence for an explicit legacy SQLite import.

| Field | Type | Rules |
|-------|------|-------|
| `import_id` | UUID | Primary key |
| `source_kind` | varchar(32) | Currently `acceptance-sqlite-v1` |
| `source_fingerprint` | char(64) | SHA-256; unique with `source_kind` |
| `started_at` | timestamptz | Required |
| `completed_at` | timestamptz nullable | Terminal states only |
| `status` | varchar(16) | `running`, `completed`, or `failed` |
| `acceptance_count` | integer | Non-negative, default 0 |
| `shadow_count` | integer | Non-negative, default 0 |
| `error_code` | varchar(64) nullable | Safe category only |

```text
running → completed
running → failed
failed → new ImportRun after correction
```

A completed fingerprint cannot be imported again. Conflicting IDs/idempotency keys abort the transaction.

## SeedRun

Evidence that an explicitly named demo dataset was applied idempotently.

| Field | Type | Rules |
|-------|------|-------|
| `seed_run_id` | UUID | Primary key |
| `dataset_name` | varchar(128) | Required |
| `dataset_version` | varchar(64) | Required |
| `checksum` | char(64) | Required |
| `applied_at` | timestamptz | Required |
| `mode` | varchar(16) | `demo` or `test`; production rejected |

Unique constraint: `(dataset_name, dataset_version, checksum, mode)`.

## Runtime-only models

- **EnvironmentConfiguration**: validated settings with secret fields excluded from output.
- **HealthComponent**: name, required flag, status, safe message code, and non-sensitive metadata.
- **CorrelationContext**: request ID propagated through headers and logs.
- **ErrorEnvelope**: stable category, safe message, correlation ID, optional field details.
- **BackupManifest**: sidecar JSON with UTC time, schema revision, checksum, tool version, and counts; never committed.
- **CapabilityContract** and **CompatibilityAdapter**: documented code boundaries, not persisted data.

## Legacy mapping

| SQLite v1 | PostgreSQL |
|-----------|------------|
| `request_json` text | `request_payload` jsonb |
| `plan_json` text | `plan_payload` jsonb |
| `gate_json` text | `gate_payload` jsonb |
| `candidate_ids_json` text | `candidate_ids` jsonb |
| `forward_json` text | `forward_result` jsonb |
| `reverse_json` text | `reverse_result` jsonb |
| `consensus_json` text | `consensus_result` jsonb |
| ISO text timestamps | parsed UTC `timestamptz` |
| integer `swap_consistent` | boolean |

The importer validates all JSON, timestamps, and IDs before the final write transaction. Any invalid row aborts the import.
